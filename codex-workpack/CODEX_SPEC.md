## 1. 使用者流程與畫面狀態

有限狀態機：`BOOT` → `HOME` → `PERMISSION_CHECK` → `READY` → `PLAYING` ↔ `PAUSED` → `IDIOM_CLEAR` → `PLAYING`；每關達標進入 `LEVEL_CLEAR` → 下一關 `READY`；逾時為 `LEVEL_FAILED`；通過第五關為 `GAME_CLEAR`。任何畫面的重新開始均明確處理。

### 1.1 首頁

- 顯示「成語彈珠臺」、操作說明、關卡概覽、玩家名稱欄、模式說明及 Start 按鈕。
- **只能使用畫面內建虛擬鍵盤完成輸入**：含數字 `0–9`、英文字母 `A–Z`、空白／刪除／清除、預設常用中文字按鈕、預設名稱清單按鈕；能在兩種鍵盤頁籤切換。支援「80401」、「王小明」、「804-01」等輸入，不提供假設能輸入全部漢字的簡陋單鍵盤。
- 名稱欄可供點選名單快速帶入；預設字、名單由獨立設定檔提供。公開倉庫預設**不可包含真實學生姓名**；若校方另有學生名單，須由使用者自行於本機或私人版本維護。
- 遊戲名稱長度 1–16 個 Unicode 字素（grapheme clusters）；去除頭尾空白，不允許空值。以 `textContent` 等安全方式呈現輸入，避免 HTML 插入。不得將姓名記錄到遠端；重新整理後不要求保留。
- 資料庫載入成功且名稱有效才可 Start；載入失敗顯示可理解的重試提示。

### 1.2 Start：權限、全螢幕、準備

- 在 Start 的**同一次使用者點擊事件處理函式中、任何 `await` 之前**，依 feature detection 立即呼叫支援的 `DeviceOrientationEvent.requestPermission()`，並可同時呼叫 `DeviceMotionEvent.requestPermission()`；把回傳的 Promise 交由 `Promise.allSettled()` 處理。
- 全螢幕嘗試亦須依使用者操作與 API 支援度執行；不能保證 Safari 允許。對 `requestFullscreen()`、`screen.orientation.lock('landscape')` 的失敗須安全降級；不得阻止玩家使用搖桿。
- 權限拒絕、事件不產生、數值為 `null`、感測器長時間沒有有效資料，都必須切換至虛擬搖桿，並顯示當前控制模式。
- 進入每關時顯示準備畫面與 `3、2、1` 倒數。傾斜模式須提供「校正水平」鍵，記錄目前平板角度為操作中性點；校正期間倒數計時不得扣秒。
- 使用者能隨時在「傾斜控制／虛擬搖桿」間切換，不得將兩者力量直接相加。

### 1.3 遊戲 HUD

- 頂端固定顯示：玩家名稱、關卡序號、主題色、剩餘秒數、當前成語序號（例如 2/5）、當前成語四字、四字的逐字注音、中文釋義、已命中字序、下一個必須碰到的字序，以及**每一字的已完成／未完成碰撞狀態**（細節見 §1.3.1）。
- 預設以四格字卡顯示 `① → ② → ③ → ④` 的完整碰撞進度，且已命中的文字必須留在進度列（即使場地物件已被吸收移除）；每個場上目標物件本身同時顯示大字及獨立的序號徽記，不能只依顏色辨認順序。
- 右上角 HUD 包含 `P` 暫停／繼續、`R` 全部重來、`A × 3` 本關重新開始（實際數字隨時更新）；三鍵可觸控區域各不小於 48 × 48 CSS px。
- `P` 在遊玩時凍結計時和全部速度，繼續後從原狀態恢復；`R` 必須先確認，再從第 1 關重新開始；`A` 必須先確認，按確認後消耗一次本關重試機會。取消不得消耗次數。
- 虛擬搖桿位於畫面左下且不遮擋重要 HUD；使用 Pointer Events 與 `setPointerCapture`，支援多點觸控。控制鍵與搖桿可同時操作。
- 當頁面隱藏、切至背景、顯示電話／系統權限提示、橫豎向切換時，自動暫停，避免不可控的倒數損失。返回後由玩家手動繼續。

### 1.3.1 四字「碰撞完成狀態」顯示（必要功能）

- **目的**：玩家不用記憶過去碰撞結果，任何時刻只看 HUD 即可知道本條成語**已完成哪些字、尚未完成哪些字，以及下一個應撞哪一字**；不得只用總分、進度條或被吸收物件消失來暗示。
- **呈現形式**：於成語與逐字注音下方顯示固定順序的四個獨立字卡，每格包含「序號＋原字＋短狀態標籤」。例如題目「守株待兔」、成功碰撞前兩字後顯示：

  ```text
  本題：守株待兔       碰撞進度：2／4
  [① 守 ✓已完成] → [② 株 ✓已完成] → [③ 待 ★下一目標] → [④ 兔 ○未完成]
  下一個要碰撞：第 3 字「待」
  ```

- **三種必要狀態**（必須在文字及視覺上明確區別）：
  - `COMPLETED`：字序小於 `nextIndex`；保留原字，顯示「✓ 已完成」，以實心或完成框線表示，**不從 HUD 移除文字**。
  - `CURRENT`：字序等於 `nextIndex`（且 `nextIndex < 4`）；顯示「★ 下一目標」或「請碰這個字」，用加粗輪廓／脈動框線醒目提示；在場上對應的目標物件加同序號外光圈。
  - `PENDING`：字序大於 `nextIndex`；顯示「○ 未完成」，採清楚但較低強調的外觀；尚未碰撞不可以呈現為錯誤狀態。
- **初始狀態**：`nextIndex = 0`，四字全數顯示；第 1 字標記 `CURRENT`，第 2～4 字標記 `PENDING`，整題進度為 `0／4`。
- **命中第 k 字**：只有物理引擎送出的、經遊戲規則核實的主滾珠直接碰撞事件，才讓 `nextIndex` 從 `k-1` 變成 `k`；下一個目標隨即改標 `CURRENT`，被命中者改標 `COMPLETED`，顯示短暫 `✓ 已碰撞「字」` 回饋。四字完成顯示 `4／4` 與「本題完成」，再進入下一題。
- **碰錯字**：無論碰到未輪到的目標字或干擾物件，僅在短時間顯示如 `尚未完成！請先碰第 3 字「待」`，場上的錯誤物件短暫閃爍；**原四格進度與 `nextIndex` 完全不變**。錯誤提示不得蓋住四格進度，也不得把未完成字誤標成已完成。
- **同字重複**：用 `charIndex` 與目標物件 ID 區分每一格，例如「日日夜夜」仍依第 1／2／3／4 格各自顯示進度；**不得**只依文字值將兩個相同字一起標為已完成。
- **重置／切題／暫停**：每開始一條新成語，四格重新回到 `0／4`；A 本關重來、R 全關重來時也依相應題目重建 HUD，絕不保留上一題殘影；P 暫停與背景暫停時保留當前四格狀態，不再接收碰撞進度；成功切題期間可以短暫保留 `4／4`，但切到新題時必須同步更新四格、注音、釋義、目標字序。
- **響應式與可及性**：在 4:3、16:10、16:9 橫向平板皆需完整看見四格（窄畫面可縮小間距但不可隱藏字或狀態）；字卡顏色外，必須包含 ✓／★／○ 及文字標籤。可在整個進度區使用 `aria-label`／適度 `aria-live="polite"` 公告**狀態變更**，但不得在每個動畫影格或感測器事件上持續朗讀。
- **單一資料來源**：狀態由 `currentIdiom`、`nextIndex`、`charIndex` 推導，顯示層不得自行持有第二份可獨立變動的進度；每次邏輯進度更新後一次性重繪四格 HUD，不能靠場上的物件是否可見推論完成狀態。

- 碰撞與計時在同一固定更新步中發生時，先處理合法命中與通關，再判定逾時，避免最後一瞬間誤判。

## 3. 場地、碰撞與物理規格

### 3.1 畫面與世界座標

- 使用 `<canvas>` 呈現場地、主滾珠、固定支柱、移動滾珠、粒子與碰撞反饋；以 DOM 顯示資訊、按鈕、注音和釋義以利可讀性。
- 採固定的**邏輯世界座標**（建議 1280×720），配合 Canvas 的 CSS 尺寸縮放及 `devicePixelRatio`（效能考量可上限 2）；使用 `ResizeObserver` 重算場地，不得因不同寬高比改變物理規則。
- 支援 4:3、16:10、16:9 橫向比例。HUD、搖桿與遊戲場地預留安全距離，物件不得生成在被 UI 覆蓋的區域。
- 固定支柱不受重力影響且速度永遠為 0；移動滾珠受同一場地重力、摩擦、牆壁與球體碰撞影響。

### 3.2 主滾珠與物件類型

- 玩家唯一可操控的主滾珠顯示「我」字，具有座標、速度、半徑、質量、碰撞彈性、阻尼。
- `targetPost`：目標字固定支柱；`targetBall`：目標字移動滾珠；`distractorPost`：非目標固定支柱；`distractorBall`：非目標移動滾珠。
- **只有主滾珠「我」直接接觸正確目標，才會計入學習進度**。其他滾珠與目標碰撞只是物理作用，不可替玩家得分。
- 目標物件每一個都存 `charIndex`（0 到 3），不能只依中文字判斷；例如同字重複出現時，也須區分第幾字。
- 干擾字應來自有效中文字，與當前成語四字不相同，且本題各干擾物件盡量避免重複。遇到來源不足要重新抽樣，不得填入亂碼。

### 3.3 運動模擬與碰撞判定

- 採 `requestAnimationFrame` 繪製，以及累積器 + **固定 1/120 秒物理時間步**；對分頁卡頓設定 delta 上限（例如 100 ms），避免物件穿牆或瞬移。
- 使用半隱式 Euler 或相近的穩定積分方式，處理 `位置、速度、加速度、阻尼、速度上限`。先做可測量的常數設定，例如最大速率、最大加速度、恢復係數及球半徑，集中放在 `config.js`，便於實機校準。
- 圓形對圓形、圓形對場地邊界都要有正確的法向速度衝量、質量比與重疊位置校正；固定支柱視為逆質量 0；主滾珠和移動球也要彼此反彈。
- 高速接近時應透過物理子步進、速度限制或連續碰撞檢測避免穿透；不得讓碰撞物件永遠黏在一起或不停抖動。
- 每題開始及重置時需進行無重疊配置：距離至少兩半徑之和加上安全邊距，避開牆壁、玩家起點與 HUD。採限定次數隨機配置 + 確定性備援配置，避免無限迴圈。
- 物理主循環不得因 60/120 Hz 畫面更新差異而改變遊戲速度；所有計時都以高精度時間或固定步累積為準。

### 3.4 命中與吸收規則

- 玩家觸碰 `charIndex === nextIndex` 時：顯示短暫吸收動畫、移除該目標物件、只前進 **1 個字序**、即時將該字字卡改為「✓ 已完成」並將下一格改為「★ 下一目標」（見 §1.3.1），同步更新 HUD 與音效／視覺反饋；主滾珠半徑保持固定，避免越玩越大而改變難度。
- 玩家觸碰未輪到的目標字、任一干擾物件：正常物理彈開，錯誤字閃爍並顯示短暫提示，不會扣除已完成字序、不會替換目標、不額外扣秒。
- 每次接觸需有「碰撞開始」判斷或短暫 cooldown，避免同一接觸在連續影格中重複命中；同一物理步最多收集 1 字，避免多物件重疊時跳關。
- 當第四字完成時顯示整條成語成功畫面，再進入下一條；暫停與關卡結算時凍結所有物理更新。

## 4. 姿態控制與虛擬搖桿

- 優先使用可取得且穩定的 `devicemotion.accelerationIncludingGravity` 估算作用於螢幕平面的重力向量；必要時使用 `deviceorientation.beta/gamma` 做替代。兩者都需做裝置橫向座標轉換，依 `screen.orientation.angle`／相容備援處理方向。
- 開始與玩家要求重新校正時，將當前平穩姿態視為中性點；以低通濾波／EMA 減少晃動，設定微小死區並將輸出限制到安全範圍。
- **傾斜方向必須與畫面上的滾動方向直覺一致**，且不因左右橫向翻轉而顛倒；特別測試 iPadOS 及 Android Chrome 的兩種橫向握法。
- 超過設定時間（建議 2 秒）未收到有效感測器值時自動使用虛擬搖桿；使用者可再試授權或重新校正。
- 虛擬搖桿以向量 `[-1,1] × [-1,1]` 給予相同的加速度控制，不是直接改寫位置；提供滑鼠操作與鍵盤方向鍵／WASD 作為桌機測試輔助。
- 統一 `InputController.getGravityVector()` 等介面，物理引擎不直接讀取瀏覽器感測器事件。切換控制方式時清空舊輸入，避免突發加速度。

## 5. 平板體驗與介面規範

- `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover">`；對 `html, body, #app, canvas` 設定 `touch-action: none; user-select: none; overscroll-behavior: none;`，避免遊戲過程雙指縮放／滑動造成捲動；但不得宣稱能阻止所有瀏覽器或系統級手勢。
- 使用 `100dvh`／安全區域 `env(safe-area-inset-*)`，處理 Safari 動態工具列和瀏海區域；優先適配 iPad 1024×768、1366×1024、Android 1280×800、常見 16:9。
- 縱向時顯示「請將平板橫放」遮罩並自動暫停；轉回橫向後手動繼續，不依賴必定成功的畫面鎖定 API。
- `requestFullscreen` 能用就用；iPadOS Safari 不支援時保持適用畫面，提供「加入主畫面／以獨立模式開啟」教學，不把全螢幕當作遊玩必要條件。PWA manifest 可做為額外改進，但不得牽涉建置工具。
- 對比度清楚；目標依「色彩 + 字序 + 閃爍／框線」多重提示，避免只靠紅綠辨認；注音文字要足夠大且與字一一對應。
- 畫面須能持續 60 FPS 為目標；在較弱裝置允許降至 30 FPS，但時間、碰撞、控制方向仍正確。避免每幀產生大量物件或 DOM 更新。

## 6. 成語資料與著作權

### 6.1 已選定的 500 條候選詞目與正式遊戲資料格式

**優先保留本次已選定的 500 條**：詳見附錄 A 與 `data/idioms_500_selection.json`。Codex 不可自行改用其他 500 條詞彙或任意更換，也不可把候選檔當作已完成的 `data/idioms_500.json`。按本次選定的 500 條逐一對照教育部 2026 版官方資料，補足、核對逐字注音及釋義。

**詞目審查與教材核對分離**：候選檔 `textbookEvidence=unverified` 表示尚未核對特定版本的教材，不得在正式說明寫成「500條確實出現在各出版社課本」。若必要，可用 `data/idiom_textbook_review.csv` 補齊出版社／年度／冊次／課次／頁碼。**未完成學段逐版核對不影響以一般成語遊戲題庫開發，但不能宣稱特定教材收錄**。

```json

  "count": 500,
  "items": [

      "idiom": "守株待兔",

```

> 上述僅為**資料格式示例**，不可作為實際 500 筆完成證明。本次已交付 500 條候選詞目，但正式遊戲 JSON 必須逐條補齊經核對的注音與釋義，完成後再通過最終資料檢核。實際需提供 500 條真實、適合國中教學、完整且正確的四字成語；注音必須與臺灣正音對應。

- 必填欄位：`id`、`idiom`、`zhuyin[4]`、`definition`、`difficulty`、`source`。`difficulty` 範圍 1–5；四字成語長度以 Unicode 字元而非 UTF-16 `length` 單純判斷。
- 所有文字用 NFC 正規化；500 個 `id` 與 500 個成語詞目各自不重複；不得有占位文字（「待補」「測試」「成語001」）、空釋義、簡體字混入、注音錯字、非四字詞或造詞。
- `zhuyin` 使用逐字陣列，有助於對齊 HUD；若需顯示合併讀音，則由畫面組合。多音字以該成語實際詞義決定。
- 題目抽樣使用可重現的種子亂數，**一次完整五關不可出現相同成語**。建議由常見度／難度形成關卡權重：第 1 關以難度 1–2 為主，第 5 關以 4–5 為主，但不改關卡秒數與數量。

- 提供 `tools/validate-idioms.mjs`（原生 Node.js，無依賴），執行 `node tools/validate-idioms.mjs`。

## 9. 自動化與人工驗收案例

0. **選詞資料（本版可執行）**：`node tools/validate-selection.mjs` 必須 PASS；500 條不重複且與附錄 A 一致。**本項通過不等於**正式注音釋義及教材版本出處已驗證。

1. **資料**：500 筆、全部不重複、格式正確；任意設定遊戲種子跑 19 題均不重複。
2. **物理**：固定支柱不移動；兩個滾珠相撞改變速度；碰壁會反彈；不能穿牆／永久重疊；畫面幀率變動不使時間加速。
3. **順序及逐字狀態**：初始四格依序為 `CURRENT, PENDING, PENDING, PENDING`，顯示 `0／4`；先撞第 3 字不加分、四格不變；撞第 1 字後變成 `COMPLETED, CURRENT, PENDING, PENDING`，顯示 `1／4` 並保留「第 1 字」在 HUD；同時觸兩目標最多前進 1；同字不同序號要各自判定；僅玩家碰撞能收集字。
4. **關卡物件及顯示同步**：每關顯示確切 4 個目標，且目標支柱／目標滾珠／干擾支柱／干擾滾珠分別符合表格；下一條成語重新生成，上一條物件與 HUD 字卡均不殘留；第 4 字命中短暫顯示 `4／4`，然後新題回 `0／4`。
5. **P/R/A**：暫停期間時間、位置與四字進度都不變；取消重試不扣次數；A 使用 3 次後禁用，仍可 R；新關恢復 A × 3；A 後題組及初始佈局一致、第一題四格重設；R 從 1 關重來並重建第一題四格。
6. **權限**：Safari 首次 Start 可彈出要求；拒絕不當機；裝置無感測器使用搖桿；旋轉裝置時自動暫停並校正方向。
7. **觸控與視覺**：搖桿與 P/A/R 能以手指操作；多指同時觸控不意外捲頁；名稱欄不須實體鍵盤可輸入與刪除；所有關卡 HUD 不重疊；4:3、16:10、16:9 均能完整看到四字、注音、`✓ 已完成／★ 下一目標／○ 未完成` 與 `x／4`，不只依顏色判定。
8. **逾時與結束**：0 秒未完成則失敗；最後一字於臨界時刻命中能正常通關；第 5 關完成顯示最終成績。
9. **部署**：使用 GitHub Pages 專案路徑，從 HTML、CSS、JavaScript 到 JSON 均正常載入；開發時透過 HTTP server，不能只用 `file://` 測試模組及 fetch。
10. **實機**：至少記錄一款 iPadOS Safari 與一款 Android Chrome 的實測結果（若無裝置則標示未測），含權限、方向、控制、畫面尺寸及長時間穩定度。
