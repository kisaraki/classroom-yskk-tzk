# Codex 執行規則：成語彈珠臺

> 本檔隨 `codex-workpack/` 放在專案子目錄。若在倉庫根目錄啟動 Codex，**必須在任務訊息中明確指示讀取本檔**；其作用範圍及自動發現方式依所用 Codex 環境而定。

## 必讀與權威

1. 先讀 `codex-workpack/START_HERE.md`、`codex-workpack/CODEX_SPEC.md` 全文；`CODEX_SPEC.md` **v1.3 為正式需求**。
2. 再讀 `docs/ARCHITECTURE.md`、`IMPLEMENTATION_PLAN.md`、`TASK_BOARD.md`、`ACCEPTANCE_MATRIX.md`、`DATA_GOVERNANCE.md`。
3. 工作包內的 `contracts/levels.json` 是硬參數鏡像；如與規格書不符，不得自行選一方，須修正鏡像或回報。
4. 開始修改前，必先完成 M0：列出倉庫檔案、既有功能、測試、Git 狀態、預設分支／Pages 路徑；禁止直接覆蓋已有程式、改寫 Git 歷史或提交私人名單。

## 強制規則

- **純前端**：HTML5／CSS3／原生 ES6+，無框架、打包、後端、CDN、外部追蹤；正式頁面可直接在 GitHub Pages 專案子路徑執行。
- **五關不可改**：時限 240/210/180/180/150 秒；需完成 2/3/4/5/5 條；各關物件種類／數量／色碼依 `CODEX_SPEC.md` §2。
- **真實物理**：固定 1/120 秒步進，圓形衝量碰撞、重疊校正、牆面反彈、固定柱與移動珠；不可用假動畫當碰撞。
- **控制**：iPadOS/Android 平板橫向；手動虛擬搖桿永遠可用。感測器授權應於 Start 使用者事件中、首個 `await` 前觸發；拒絕或無資料自動降級。
- **姓名輸入**：只使用畫面內建虛擬鍵盤，支援字母、數字、刪除、清除、候選字／名稱；不得附帶真實學生名單，也不得對外傳送玩家識別資料。
- **HUD 必備**：每題的四字、注音、釋義、`0/4`～`4/4` 和逐格 `✓已完成／★下一目標／○未完成` 隨時一致；即使碰中物件消失，字卡仍保留原字。以 `charIndex` 而非文字值識別字序。
- **P/R/A**：P 暫停不消耗進度、R 確認後全關重來、A 確認後本關限 3 次，均需處理倒數、題目及視覺狀態。
- **題庫誠信**：保留既有 500 個候選成語。正式題庫須合法來源、每字注音、完整釋義和人工核對；不准 AI 憑空補入／宣稱 500 條已通過。學段不代表教材收錄。
- **程式品質**：集中常數、模組化可測、處理錯誤與切頁、無未處理 Promise 拒絕、無不必要的動態 HTML 注入、所有網站資源採相對路徑。
- **先測再宣稱**：跑 `node codex-workpack/tools/verify-workpack.mjs`、根目錄的單元測試及任何可行整合測試；實機結果若未測必須標明未測。

## 執行方式與停止條件

從 M0 按 `docs/IMPLEMENTATION_PLAN.md` 的 M1→M5 逐關完成；每階段需確有可操作成果，而非只有畫面示意。遭遇 GitHub 沒權限、官方授權無法確認、正式 500 條未核校、無實機時，繼續能安全完成的工程部分，但標記該驗收關卡 `BLOCKED`，不可冒稱整案完成。

## 每階段必須回報

- 階段及狀態（DONE／PARTIAL／BLOCKED）。
- 新增／變更檔案（路徑與目的）。
- 實際執行的測試指令與結果（非預測）。
- 關卡配置與規格差異（若有）。
- 尚存問題、必要人工審核、下一步。
- 不可假稱已推送 GitHub、已發布 Pages、已核對官方資料或已在實機上測試。

記錄可依 `docs/REPORT_TEMPLATES.md` 格式撰寫，勿改寫官方核校簽核紀錄。
